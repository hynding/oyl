# @oyl/camis-php-oyl

The OYL sync API as a Laravel app generated by [camis](../../../camis) — a drop-in for
`apps/strapi-oyl` that runs on PHP shared hosting (DreamHost). Nothing per content type is
written here: `camis.json` is imported from the Strapi app's schemas, `roles.json` is derived
from `@oyl/all-of-oyl`'s `KINDS`, and `laravel/` is regenerated on every build.

## Prerequisites

- The camis repo checked out beside this one at `../../../camis` with `pnpm install` run there
  (this package links `@camis/cli` from it).
- `php` 8.3+ (`pdo_sqlite`, `mbstring`, `openssl`; Filament wants `intl`) and `composer` on PATH.

## Commands (from the repo root)

```bash
pnpm php-app import   # strapi-oyl schemas → camis.json, then roles.json
pnpm php-app build    # scaffold laravel/ if missing, then camis build (+ overlay)
pnpm php-app dev      # php artisan serve on :1340 with a dev SQLite (do not run with strapi-oyl)
pnpm php-app test     # generator drift + overlay lint tests
E2E_BACKEND=php pnpm e2e   # the acceptance gate: the browser suite against this backend
pnpm deploy:dreamhost # rsync + remote composer/artisan (config: OYL_DH_* in root .env)
```

## What is committed

| File                                                                  | Purpose                                                                                                         |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `camis.config.json`                                                   | camis project config: IR, roles, `overlay/` as the protected dir, one filament target with `apiStyle: "strapi"` |
| `camis.json`                                                          | IR imported from `../strapi-oyl` (generated; reviewable diffs)                                                  |
| `roles.json`                                                          | one `authenticated` role derived from `KINDS` (generated)                                                       |
| `overlay/routes/api-custom.php`                                       | `GET /bootstrap` and `GET /google/config`                                                                       |
| `overlay/app/Http/Controllers/Api/ConsumableProductApiController.php` | UPC dedup + UPC-implies-public                                                                                  |
| `.env.example`                                                        | production env template (MySQL, `SANCTUM_TOKEN_EXPIRATION`)                                                     |

## DreamHost one-time setup

1. Create a MySQL database + user in the panel; put them in `laravel/.env` on the host
   (start from `.env.example`) and run `php artisan key:generate --force` once.
2. Point the API domain's web directory at `<OYL_DH_APP_ROOT>/laravel/public`.
3. Confirm the domain runs PHP 8.3+ with `intl` enabled.
4. Make `laravel/storage` and `laravel/bootstrap/cache` writable by the PHP user.
5. The Strapi-style `username` migration assumes an empty `users` table — deploy before
   anyone registers.
6. Add to the untracked root `.env`: `OYL_DH_SSH=<user>@<host>`, `OYL_DH_APP_ROOT=<path>`,
   `OYL_DH_SITE_URL=https://<api-domain>`.
