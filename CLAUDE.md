# CLAUDE.md

Operator notes for working in this repo. Keep terse; update when something changes.

## What this is

OYL ("Organize Your Life") — a personal productivity stack covering daily activities, goals, and nutrition tracking. pnpm workspace monorepo. Eight members: a shared zero-dependency TS domain core (`@oyl/all-of-oyl`), a domain-agnostic Stencil component library (`packages/ui-oyl`), a flagship vanilla-JS app (`apps/vanilla-oyl`), its Stencil successor (`apps/stencil-oyl`, shell only so far), a Strapi backend (`apps/strapi-oyl`), a camis-generated PHP backend (`apps/camis-php-oyl`), a Playwright browser e2e suite (`apps/e2e-oyl`), and a receipt/document parsing CLI (`packages/ocari-oyl`).

`apps/` is the home for all apps; everything shared lives in `@oyl/all-of-oyl` `src/` (the single source of truth). The legacy stack (`next-oyl`, `react-oyl`, `storybook-oyl`, `strapi-oyl`, `e2e-oyl`, the old `vanilla-oyl` testbed, `vendors/firebase`, and the `all-of-oyl` `modules/`+`vendors/` barrels) was removed on 2026-06-16 — **preserved on branch `legacy/2026-06-16`** if you need to reference or restore any of it.

## Dev workflows

Root filter shortcuts. From the repo root:

```bash
pnpm dev                 # FULL STACK: backend on 1340 + app on 8041, health-gated, one Ctrl-C stops both
pnpm dev:watch           # …plus rebuild+revendor all-of-oyl on every src/ change
pnpm dev:fresh           # …plus wipe apps/strapi-oyl/.tmp/data.db first
pnpm dev:stencil         # backend on 1340 + apps/stencil-oyl (Stencil dev server) on 3344
pnpm all-of test         # Vitest on the shared lib (src/)
pnpm all-of build        # Emit browser ESM to packages/all-of-oyl/dist
pnpm ui dev              # ui-oyl showcase (stencil dev server) on 3443
pnpm ui build            # ui-oyl prod build: dist + custom elements + readmes + dist/themes
pnpm ui test             # ui-oyl: @stencil/vitest (dev build, then spec + unit projects)
pnpm stencil dev|build|test|typecheck   # stencil-oyl (each builds all-of-oyl + ui-oyl first)
pnpm strapi-app develop  # Strapi backend dev alone (port 1340 native, 3340 in docker)
pnpm vanilla dev         # app alone: build all-of-oyl → vendor into the app → http-server on 8041
pnpm vanilla test        # Vitest (happy-dom) on the app
pnpm e2e                 # Playwright e2e: vanilla (8042) + stencil-oyl (8043) projects, backend on 1341 (all auto-start)
pnpm ocari <image…>      # parse receipt/document images → named copy + JSON sidecar (needs local Ollama)
pnpm php-app run import  # strapi-oyl schemas → camis.json + roles.json (commit both)
pnpm php-app build       # scaffold laravel/ if missing, then camis build
pnpm php-app dev         # PHP backend on 1340 (never with strapi-app develop)
E2E_BACKEND=php pnpm e2e # browser suite against the PHP backend (Strapi-compatibility gate)
pnpm deploy:dreamhost    # manual deploy of committed HEAD to DreamHost, both targets (config: OYL_DH_* in untracked root .env; --dry-run, --only www|api). CI does this on every push to master (.github/workflows/deploy.yml)
```

Docker — the full app stack (postgres + backend + app):

```bash
docker compose up -d --build postgres strapi-app vanilla
```

Then at `http://localhost:8041` go to **Status → Connection**, set the backend URL to `http://localhost:3340/api`, mode **Remote**, **Apply & reload**, and sign in (Account). `strapi-app` uses Postgres database `oyl_app`; if your `database-data-oyl` volume predates this, run `docker compose down -v` once so the `CREATE DATABASE oyl_app` init runs. Don't run native `pnpm vanilla dev` and the composed `vanilla` together — both bind host `8041`. Both compose services share one image (`oyl-app:dev`, built from `Dockerfile.app`).

## Development practices

- **Definition of Done (every change):** the affected package's tests, typecheck, and — for `all-of-oyl` — `pnpm all-of build` (DOM-safety) are green. Never commit on red. Run the strict gate `pnpm all-of typecheck:src` when touching `src/`. **UI-facing or API-facing changes also run `pnpm e2e` green** — and every new screen/feature/route gets (or extends) a spec in `apps/e2e-oyl/tests/` (conventions in `apps/e2e-oyl/README.md`: hygiene allowances for intentional failures, per-test users, unique catalog names, persistence asserts only for backed collections).
- **TDD:** write the failing test first, then minimal code to pass, then commit. Tests assert observable behavior, not internals (e.g. assert via a component's own shadowRoot/props — see the shadow-DOM note in memory). Never weaken a type/lint rule or add throwaway markup just to make a test pass.
- **Architecture:** shared logic lives only in `@oyl/all-of-oyl/src` (never duplicated in an app); register persistable types in `src/collections.ts`. Keep files small and single-responsibility. DOM/Web globals are injected via interfaces, never referenced directly in `src/`.
- **Workflow for non-trivial work:** brainstorm → spec (`docs/superpowers/specs/`) → plan (`docs/superpowers/plans/`) → TDD implementation → review. Specs/plans are the archive of _why_, kept even after merge.
- **Git:** branch off `master`; small, frequent, behavior-scoped commits with a clear prefix (`feat`/`fix`/`refactor`/`chore`/`docs`); end commit messages with the `Co-Authored-By: Claude …` trailer. Commit/push only when asked.

## Conventions and gotchas

- `@oyl/all-of-oyl` is the workspace single source of truth: the bare specifier hits `src/index.ts`; `/format` (`src/format/`) the shared DOM-free value-formatters (`formatMoney`/`formatNutrients`/day+cadence helpers — never duplicate these app-side). Both apps depend on it via workspace protocol. Only `apps/vanilla-oyl` consumes the built `dist/` (browser ESM, via importmap + a vendored copy; it carries importmap entries + vendored copies for `/format` and `/client` too); `apps/strapi-oyl` and the typecheckers run against the TS source.
- New shared business logic goes in `@oyl/all-of-oyl/src` (never duplicated in an app). When adding a persistable type, register it in `src/collections.ts` so every app and the backend pick it up. `src/` is `"type": "module"` + NodeNext, so all relative imports need explicit `.js` extensions. **Anything in `src/` that touches Web/DOM globals must be injected via a minimal interface** (the browser build tsconfig has NO DOM lib — `pnpm all-of build` is the gate); see `src/core/http-repository.ts` (`FetchFn`) and `src/core/local-storage-repository.ts` (`StorageLike`). The build guard (`scripts/check-no-bare-imports.mjs`) fails if `dist/` ever gains a bare-specifier import (would break the importmap).
- **Routing is HTML5 History API** (clean paths like `/journal`, not `#/journal`): `packages/all-of-oyl/src/client/session/route.ts` (`parsePath`/`createRouteState`/`navigate`, fed by `popstate`) + `src/state/link-interceptor.js` (one delegated `document` click listener captures same-origin anchor clicks across the shadow boundary via `composedPath()`). `/` redirects to `/status`. Route name = first path segment (the seam for future nested routes); the route signal stays `Signal<string>` so `oyl-nav`/`oyl-router` are unchanged. `navigate(path, { replace: true })` uses `replaceState` (no history growth) — used for forced-login redirects.
- Auth routes: `/login` + `/register` (dedicated pages; account required — no skip/local-data option); `/profile` (identity, profile fields, connection/sync, data actions). Auth moved OUT of the Status screen. Forced login when no session (`client/session/auth-guard.ts`).
- **`defaultStorageMode` is `'remote'` on every host, localhost included** (`client/storage/config.ts`) — the app is online-first/account-required, so `pnpm dev` needs no Status configuration: a fresh profile boots against `DEFAULT_API_BASE_URL` (`http://localhost:1340/api`) and the guard redirects to `/login` _before_ any network call. `'local'` is never a host-derived default any more; it is only ever an explicit Status → Connection choice (an explicit stored choice still wins), kept as the basis for the deferred private mode. Docker is the exception — it publishes the backend on 3340, so the composed stack still needs the URL set by hand.
- Header `oyl-account-menu` (toolbar slot): Profile link always; Log out when signed in, Sign in when not.
- Effective-timezone seam: `client/stores/profile.ts` (current-user record) + `resolveTimezone(profile, browserTz)` resolves tz at boot; injected into `createDataState` and every screen's `view.tz`; tz/units changes save+reload.
- **Client state lives in `@oyl/all-of-oyl/client`, never in an app.** Stores, the signals core, bootstrap/outbox wiring and session state are shared by vanilla-oyl and the upcoming stencil-oyl. App-only pieces stay app-side: vanilla's `OylElement`, `link-interceptor`, theme/layout state, and `storage/browser-ports.js` (real `crypto.randomUUID` / `navigator.storage.estimate` / build marker, passed into `makeRepositories`/`createDataState`). **Exactly one copy of the reactive core may load**: never deep-import `@oyl/all-of-oyl/client/...` or keep a local `signal.js` (two tracking contexts = screens silently stop updating; `apps/vanilla-oyl/test/client-entry.test.js` guards it).
- `@oyl/all-of-oyl/format` also exports body formatters: `formatWeight(kg, units)`, `formatHeight(cm, units)`, `age(birthday, today)` (both dates `YYYY-MM-DD`).
- Entry kinds are split across screens: the Journal day-list excludes `transaction` (→ Finance) and `consumption` (→ Nutrition), showing only notes/measurements. The `/nutrition` screen surfaces the `Consumable` catalog + `Consumption` logging with daily `sumNutrients` totals (`oyl-nutrition*` components; `client/stores/journal.ts` `consumptionsOn`/`dailyNutrients`; `client/stores/consumables.ts`). The catalog type is `Consumable` (was `Food`); nutrient helpers live in `@oyl/all-of-oyl` `nutrition/nutrients.ts`.
- `apps/vanilla-oyl/index.html` asset paths **must stay root-absolute** (`/src/…`, `/vendor/…`, `/styles/…`, importmap `/vendor/all-of-oyl/index.js`) — relative `./` paths break on multi-segment deep links (`/journal/2026-06-16`). Don't "tidy" them back to `./`.
- `pnpm vanilla dev` runs `http-server … --proxy http://localhost:8041?` for SPA fallback (serves `index.html` for unresolved deep paths). Gotcha: it returns `200` + index.html for **any** unresolved path, so a genuinely-missing asset (typo'd `/vendor/foo.js`) is masked as a 200 HTML response instead of a 404.
- `rrule` quirk: it ships as a CJS default-export. Import as `import rrule from 'rrule'; rrule.rrulestr(...)` (the named `rrulestr` is undefined on some resolvers).
- `apps/strapi-oyl` routes mount under Strapi's `/api` prefix → `ApiClient` base URL is `http://host/api`. Routes are JWT-gated; `authenticated` role is granted only the relevant content-type actions via bootstrap (`src/index.ts`). Writes upsert by domain `recordId`. CORS (`config/middlewares.ts`) allows `http://localhost:8041`.
- **Boot is ONE request:** `GET /api/bootstrap` (custom non-content-type route, `src/api/bootstrap/`) returns every backed collection (personal owner-scoped + catalog public-or-mine) keyed by REST plural path; the client's `refresh()` decodes it via `decodeBootstrap` and hydrates all stores with zero per-collection reads (falls back to fan-out reads if the endpoint 404s). Client-side, `BACKED` (personal) and `CATALOG_BACKED` (catalog) in `packages/all-of-oyl/src/client/storage/bootstrap.ts` gate which collections get live clients — `lifeAreas` has NO Strapi content-type yet, so it must stay out of `CATALOG_BACKED` (a live client 404s `/api/life-areas`). When adding a content-type, also add it to the `/bootstrap` controller + these gates.
- **Google sign-in + Drive is server-brokered** (`apps/strapi-oyl/src/api/google/`): the backend owns the OAuth code exchange and token storage; requested scope is `drive.file` only (app-created files only, never full Drive). Unset `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` hides the feature entirely — the app works identically without them. The OAuth callback hands the session back via a URL fragment (`#google=<jwt>`, adopted in `client/session/auth.ts` before the login guard runs). The Drive client (`packages/all-of-oyl/src/google/`) is DOM-free with an `AccessTokenProvider` seam for future consumers. e2e drives a standalone fake-Google fixture server on port 1342 (`apps/e2e-oyl/scripts/start-fake-google.mjs`).
- **stencil-oyl gotchas:** it runs `@oyl/all-of-oyl` from the package's `dist/` — after editing `packages/all-of-oyl/src`, rebuild (`pnpm all-of build`; the `pnpm stencil …` scripts do it) or the app runs stale code. Exactly ONE reactive core: `src/global/app.ts` imports the client layer into the shared chunk and a unit grep forbids any other `signal`/`effect` source; a spec that creates a signal must take it from the bundle (`core()` in `vitest-setup.ts`) or the component never reacts. Every `ui-*` tag a component renders must be registered in `src/global/app.ts` (`defineCustomElementUiX()`; a unit test enforces it) — Stencil treats foreign tags as plain elements. Callbacks are `@Event()`s (`onX` props are refused by the compiler); modules with `@Component` export only the class. Screens render in `oyl-router`'s light DOM (so `oyl-status h2` style selectors work). `flush()` returns at once mid-drain by design, so "drained" is observed through the outbox size (`flushAndRefresh`). Clicks in specs go to a `ui-button`'s inner control, as a user's do.
- **ui-oyl gotchas:** component CSS may reference only token names in `packages/ui-oyl/src/global/contract.ts` (plus component-private `--_*`); add a name there and in `tokens.css` together. Theme files are copies of vanilla's — change a theme in vanilla first. happy-dom has no `attachInternals`; `vitest-setup.ts` shims the members the library uses and records `setFormValue` on the host as `__formValue` for specs. Don't set `noEmit` in its `tsconfig.json` (Stencil's transpile then finds no components). Custom events never reuse native names (`uiInput`, not `input`). The artifact/claude.ai host rewrites `<link>`s, so verify themes with `pnpm ui dev` or headless Chromium, not a published artifact.
- Shadow-DOM styling: `reset.css` does NOT reach shadow roots — shared shadow base rules (border-box sizing, focus ring) live in `baseStyles` in `src/lib/reactive/oyl-element.js`. On ≤640px viewports `oyl-nav` docks as a fixed bottom tab bar (viewport-fixed — that's why `oyl-shell`'s `:host` must NOT have `container-type`, which would trap `position: fixed`) and `oyl-shell` reserves matching `.page` bottom padding.
- **Status-screen tools are account-scoped** (online-first): Load demo data / Download backup / Import backup operate on the signed-in account THROUGH the stores (writes flush via the outbox; server upserts by id) and are enabled in Remote mode only; Reset local data stays Local-mode-only. Demo seed = `seedAccount` in `packages/all-of-oyl/src/client/storage/seed.ts`: `makeSeed(today)` re-anchors the fixture slice to the real today, and `remapIds` re-mints every record id per seeding (fixture ids are constants but `recordId` is globally unique server-side — two accounts must not collide). `?seed` on the URL seeds only an EMPTY signed-in account ("empty" = personal collections only — the shared catalog doesn't count). Export/import round-trip the same wire shapes `loadDataset` accepts.

The `camis-php-oyl` tests fail if either generated file drifts. **Schema change ⇒ Strapi sync before PHP deploy**: boot strapi-oyl against the target database (locally `pnpm strapi-app develop`; DreamHost per the package README "Schema sync") before **pushing to master** — otherwise the CI deploy's `camis:strapi-schema-check` fails _after_ the api upload, so a push without the sync leaves the new api live against the old schema (www not published) until the sync is done and the workflow re-run.
